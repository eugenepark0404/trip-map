# Trip Map

A travel diary where your trips fill in a map of Korea. Pick a cover photo for each region, write a diary entry, and watch the map turn into a collage of the places you have been. Maps can be shared with friends.

Built with React, TypeScript, Vite, Tailwind CSS and Supabase.

## Why I built it

I love travelling around Korea, and the photos from those trips just pile up in my phone gallery. I wanted to choose one representative photo per region and write a diary about it. Instead of a list of entries, I wanted the result to look good, like colouring in a map, so the photo itself fills the shape of the region.

It started as a personal curiosity project.

## Features

- **Korea boundary map** (SVG) with pan, zoom and pinch. Region names appear as you zoom in, and rivers are drawn as light lines.
- **Diary per region**: date, text, rating and a revisit list. One diary can cover several regions, and a region can have several diaries (several visits).
- **Cover photo placement**: the photo is scaled, rotated and positioned inside the merged outline of the selected regions, and shown on the map clipped to that shape. Regions with entries get a fill colour.
- **Bucket notes**: a quick "want to go" note, separate from travel diaries.
- **Shared maps**: create several maps, invite friends by email, and manage members and deletion from the map settings. Favourite maps are pinned to the top.
- **PWA**: installable on a phone.
- Private photo storage: only map members can see photos.

## How it was built

- **Frontend**: React 19, TypeScript, Vite, Tailwind CSS v4, react-router, `react-zoom-pan-pinch`, `vite-plugin-pwa`.
- **Backend**: Supabase (email auth, Postgres, Storage) with row-level security based on map membership. The schema is in `supabase/migrations/`.
- **Map data** is generated by scripts:
  - `scripts/build-regions.mjs` builds `public/regions.geojson` from administrative-dong boundaries (vuski/admdongkor), merged with `turf` to city/county level. Seoul and Incheon keep districts, and islands such as Dokdo are split out.
  - The region and province boundaries are simplified together as one topology (`topojson-simplify`), so shared borders have no gaps.
  - `scripts/build-rivers.mjs` fetches the major rivers from OpenStreetMap.
- Drawing uses `d3-geo`. A diary photo is clipped to the union of its regions by putting each region's `clipPath` in one SVG group, so no server-side geometry merging is needed.
- Deployed on Vercel (`vercel.json` rewrites routes to `index.html`).

```
src/
├─ components/   # KoreaMap, DiaryForm, PhotoPlacementEditor, Sidebar, MapSettingsPanel, ...
├─ context/      # AuthContext, MapContext, DiaryContext
├─ lib/          # photo placement, Supabase client, helpers
└─ pages/        # HomePage, LoginPage, SignupPage
scripts/         # map data and icon generation
supabase/migrations/   # schema and RLS policies
```

## How to use it

1. Install dependencies:

   ```bash
   npm install
   ```

2. Create a Supabase project, then copy `.env.example` to `.env` and fill in:

   ```
   VITE_SUPABASE_URL=
   VITE_SUPABASE_ANON_KEY=
   ```

3. In the Supabase SQL editor, run the files in `supabase/migrations/` in order (`0001` to `0006`). They create the schema, RLS policies, invites, photo storage and favourites.

4. Start the dev server:

   ```bash
   npm run dev
   ```

Then sign up, create a map, double-click a region to open its diary, and press **+** to write a travel note or a bucket note.

Other scripts: `npm run build` (type-check and build), `npm run lint`.
